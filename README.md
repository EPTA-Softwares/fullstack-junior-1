🧪 Teste Desenvolvedor Fullstack Junior 1

📌 Sobre o teste

Este teste tem como objetivo avaliar sua capacidade de:

* Entender e interpretar requisitos;
* Estruturar uma solução;
* Escrever código limpo e organizado;
* Tomar decisões técnicas;
* Trabalhar com boas práticas de desenvolvimento;
* Criar uma interface funcional e responsiva;
* Documentar sua solução.

Importante: não esperamos necessariamente uma solução perfeita. Queremos entender principalmente como você pensa e como estrutura seu código.

⸻

🎯 Desafio

Seu objetivo é criar é o web app [*drivo*], uma plataforma onde você vai montar sua garagem com seus veículos de forma facilitada com Inteligência Artificial.

O usuário deve conseguir:

* Fazer Login;
* Fazer Cadastro;
* Visualizar seus veículos;
* Pesquisar um veículo;
* Criar um novo veículo;
* Importar um CRLV;
* Utilizar a API gratuita do GEMINI para realizar o scan e o preenchimento automático dos dados do CRLV;
* Editar um veículo;
* Excluir um veículo;
* Alterar dados cadastrais;
* Fazer Logout.

⸻

📋 Requisitos

* Front End (Next JS ou Tanstack Router)
* Back End (Nest JS ou fastify)
* Boas práticas de programação
* Tailwind CSS
* Postgres
* Docker

🔌 API / Backend

A aplicação deverá consumir uma API REST responsável pelo gerenciamento dos veículos

A API deverá seguir os padrões HTTP e retornar os dados em formato JSON

*Obrigatório*
* Uso da API gratuita do GEMINI para realizar retirar as informações de um CRLV e preencher automaticamente os dados
* Rotas mínimas para o funcionamento do sistema
* Autenticação com JWT

⸻

📦 Entrega

O projeto deve ser disponibilizado em um repositório Git em um *Único Repositório* contendo FrontEnd e BackEnd.
A ausência do BackEnd ou do FrontEnd desqualifica o candidato imediatamente.
É obrigatório um arquivo *docker-compose* e *Dockerfile* para subir os sistemas em um único comando.

O repositório deve conter:

* Código-fonte;
* README;
* Arquivos necessários para execução;
* .env.example, caso existam variáveis de ambiente;
* Dockerfile
* docker-compose.yml

O README deve explicar

1. Como instalar o projeto;
2. Como executar o projeto;
3. Como executar os testes;
4. Quais decisões técnicas foram tomadas;
5. Quais limitações existem;
6. O que seria feito caso houvesse mais tempo.

⸻
